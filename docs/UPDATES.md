# Автоматические обновления

GigaFlow использует Sparkle 2.10.1. В приложение встроен публичный ключ Ed25519; закрытый ключ остаётся на Mac издателя. Подпись архива проверяется до распаковки, а подпись appcast — до использования сведений о выпуске. Это отдельная идентичность от постоянного сертификата подписи приложения: для будущих обновлений нужны обе.

Адрес ленты:

```text
https://github.com/aspalagin/GigaFlow/releases/latest/download/appcast.xml
```

Каждый новый GitHub Release содержит `appcast.xml`, DMG и `SHA256SUMS.txt`. Сначала все файлы загружаются в черновик; только после проверки выпуск становится публичным и последним. Поэтому лента не указывает пользователям на ещё не опубликованный установщик.

## Однократная подготовка ключа

На Mac издателя:

```sh
xcrun swift scripts/setup-update-signing.swift
```

Скрипт выводит только публичный ключ и сохраняет пару в `~/Library/Application Support/GigaFlow/UpdateSigning`. Закрытый ключ `private-key.base64` имеет права `0600`, папка — `0700`. Повторный запуск сохраняет существующую идентичность; повреждённые или несовпадающие ключи не заменяются автоматически. Для проверки без создания файлов используйте `--check`.

Для изолированных тестов генератор принимает `--directory /absolute/path`; `make-appcast.sh` поддерживает соответствующий `GIGAFLOW_UPDATE_SIGNING_DIR`. Закрытая идентичность внутри репозитория не принимается.

Публичное значение переносится в `SUPublicEDKey` файла `app/Info.plist` до сборки. Включены `SUVerifyUpdateBeforeExtraction` и `SURequireSignedFeed`. Приватную папку необходимо сохранить в защищённой резервной копии вне репозитория и release assets. Потеря ключа не исправляется простой генерацией новой пары: уже установленные клиенты доверяют прежнему ключу.

## Очередной выпуск

1. Увеличьте `CFBundleShortVersionString` и числовой `CFBundleVersion`. Соберите и проверьте финальный DMG обычным release-процессом, сохранив прежний сертификат подписи приложения и ключ обновлений.
2. Для второго и последующих выпусков скачайте опубликованный `appcast.xml` последнего релиза в отдельный локальный файл. Он содержит уже опубликованные записи; генератор проверяет его подпись и сохраняет эти записи.
3. Выполните:

```sh
bash scripts/make-appcast.sh dist/GigaFlow-0.4.0-arm64.dmg
# Для следующего выпуска с сохранением ранее опубликованных записей:
bash scripts/make-appcast.sh dist/GigaFlow-0.4.1-arm64.dmg /path/to/previous-appcast.xml
```

Без второго аргумента существующий `dist/appcast.xml` используется как предыдущая лента. При первой сборке этого файла ещё нет. Готовая подписанная лента записывается в `dist/appcast.xml`; исходники и GitHub скрипт не изменяет. Он читает метаданные непосредственно из DMG, сверяет публичный ключ с приватной идентичностью, использует официальные инструменты Sparkle и проверяет обе полученные подписи. Образы и вложенный код не переподписываются на этом этапе. Delta-обновления пока отключены.

4. Создайте черновик GitHub Release для точного коммита сборки. Загрузите DMG, `SHA256SUMS.txt` и `appcast.xml`, проверьте размеры и серверные SHA256; затем опубликуйте релиз как latest.
5. Проверьте, что публичный адрес ленты возвращает новый подписанный XML и что его enclosure ведёт на доступный установщик.

После генерации нельзя вручную редактировать XML: это нарушает подпись. Для повторной генерации используйте тот же финальный DMG. Скрипт отклоняет попытку заменить сведения об уже существующем выпуске и попытку понизить номер сборки.

Установленные версии до появления Sparkle не умеют получать это обновление автоматически. Им требуется один обычный переход на версию с механизмом обновлений. Подпись Developer ID и notarization по-прежнему отсутствуют; на новом Mac первоначальный запуск выполняется через штатное разрешение macOS для GigaFlow.

## Изолированные проверки инструментов

```sh
python3 -I scripts/check-update-tools.py
```

Проверки запускаются на macOS с Command Line Tools. Они создают временные ключи и маленькие тестовые DMG, проверяют отказ от повреждённого архива, подменённой ленты, неверного ключа и понижения версии, затем удаляют временные файлы. Настоящие ключи издателя и установленный GigaFlow не используются.

Документация: [настройка и подписи Sparkle](https://sparkle-project.org/documentation/), [параметры безопасности](https://sparkle-project.org/documentation/customization/).
